# collab/proposals — 提案写作规则

替代已废止的 b-*/f-* 成对信件：每个议题一个文件，讨论聚拢在议题文件内联线程里。

## 规则

- **一议题一文件**：命名 `NNN-<slug>.md`（NNN 三位递增编号，不重用；slug 为英文 kebab-case）。
- **front-matter**：`proposal`（编号）、`title`（议题）、`status`（状态字段）、`author`
  （提出方 wt/角色）、`date`（提出日期）。
- **正文结构**：`## 背景`（证据与上下文）→ `## 提案`（期望动作，可列点）→ `## 内联讨论线程`。
- **状态字段**：`提出 → 讨论中 → 已接受 / 已拒绝 / 已撤回`。状态变化即改 front-matter 的
  `status`，并在讨论线程末尾追加一条带日期的结论记录。
- **内联线程**：回复按时间追加 `### 回复（<角色或 wt>，YYYY-MM-DD）` 小节；反提案直接写在线程里，
  不另开文件。
- **关闭后不再修改**：已接受/已拒绝/已撤回即关闭，文件内容冻结（实例有自然生命周期）。
  已接受的议题由持有方按切片落地，落地后从 BOARD 开放问题表移除或标记。
- **入口与归档**：新议题先登记进 collab/BOARD.md 开放问题表再开文件；关闭的提案保留原位，
  靠 git 历史检索，不设归档目录。
