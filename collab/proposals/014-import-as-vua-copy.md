# 014 「导入为 VUA 管理的副本」写路径提案（M6 T-A 延伸）

> proposal: 014
> title: 导入为 VUA 管理的副本（唯一写路径的任务化语义：确认链/守卫/审计/恢复）
> status: 提出
> author: 环境/wt-6
> date: 2026-09-09

## 背景

- 用户裁决 U3（product-boundary 1.2.0）：VUA 对 ALCOM/VCC 管理的原项目只读；唯一写
  路径是用户显式选择的「导入为 VUA 管理的副本」。1.2.0 已钉死五项规格：新项目路径＋
  新项目身份；明示预计磁盘占用；不复制可再生目录与旧任务状态；导入后重新 Inspect
  （不继承原项目的确认/快照）；保留来源关系。
- 用户裁决（2026-09-09 操作者派发）：M6 T-A 提前开工，但任务包明确「提案前只做只读
  能力检测与 Rust 侧实现」。写路径不在只读面内，按提案 013 R5（写命令各自需要独立
  提案）立本提案。
- 桌面 T-C（F6 项目兼容页）已交付诚实占位并留言：检测读面与副本导入执行落地后请
  知会桌面接线——本提案是桌面接线的语义前置。

## 提案（裁决项，逐项待表态）

- **R1 语义（1.2.0 五项规格照录，不扩展）**：导入产生新项目目录（用户选择的目标父
  目录＋项目名）；复制范围＝原项目的 Unity 工程内容；**排除**可再生目录
  （`Library/`、`Temp/`、`Logs/`、`obj/`、`Builds/` 等）与 `.vua/`（旧任务状态、锁、
  标记一律不随行）；完成后对新项目执行完整 Inspect；新项目 `.vua/` 内记录来源关系
  （源路径＋源管理器关联＋导入时间戳），便于返回。
- **R2 确认链**：计划（含来源/目标路径、磁盘占用预估——按复制范围实际统计，非猜测、
  排除清单明示）→ 用户显式确认 → 执行 → 复检（新项目 Inspect 结果回执）。确认走
  桌面 UI 经版本化应用契约；命令面归属与词表路由核心（与提案 013 同框架，作为其
  写命令附录或独立命令另立词表行，由核心裁决）。
- **R3 守卫（执行前逐项核验，任一不符即拒绝并降级为诊断）**：目标路径已存在＝拒绝；
  目标位于源项目目录内部＝拒绝；源路径必须是检测面（project-inspection）识别的
  在册项目＝否则拒绝；磁盘余量低于预估＋安全余量＝拒绝；导入过程中获取**新项目**
  变更锁（原项目只读，不取锁不写标记）。
- **R4 审计与恢复**：导入是可恢复任务（任务化、收据、失败如实失败）；中断/失败后
  **不隐式续传**——残留的新项目目录半成品由复检标记 `inspect_required`，等用户显式
  决定（重试＝清理后重来，或放弃＝用户手动删除）；任务记录排除清单与实际复制的
  顶层条目清单（审计面）。
- **R5 非目标**：不修改原项目的任何文件；不回写 ALCOM/VCC 的注册表/数据库/设置
  （新项目登记为 VUA 管理是 VUA 侧事实，不通知外部管理器）；不提供批量导入
  （一次一项目）；不做跨盘符特殊优化（按普通复制语义，慢如实慢）。
- **R6 裁决流程**：核心（任务面/路由/词表）与桌面（交互形态——与 T-C 四项交互形状
  确认请求合并处理）表态 → 集成仲裁 → 语义冻结 → 环境实现（Rust 侧 project-manager
  域 + 测试）→ wire 接线随 013 词表。裁决前环境不实现写路径，桌面保持占位。
