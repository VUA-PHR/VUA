## 0. 面板使用规程（夜间操作者先读，再翻条目）

### 0.1 三层分流门禁——不是所有分歧都进面板

收到一个"要不要裁"的问题时，按顺序过三问：

1. **域内权威？**（数据对 bdl-commands 词表命名/字段、桌面对 UI 交互细节、环境对标识文件
   格式、核心对路由——AGENTS.md「域 Schema 冻结责任归域角色」＋013/014 先例）
   → 归该角色自决，**不进面板**。
2. **跨域仲裁？**（排期冲突、词表归属争议、两域表态分歧——collab/README 合并纪律）
   → 归集成仲裁，**不进面板**。夜间集成实例在场（wt-main）时必须先走集成；
   集成缺员时该问题**挂起留晨起**，面板不得代行仲裁（见 G-4）。
3. **本应 [需用户] 级？**（升级规则触发条件：需猜测才能继续／涉及安全、法律、付费资产、
   产品边界／进程间无法收敛）→ 进面板。但见下条红线。

### 0.2 红线——预授权不覆盖，一律留晨起

用户预授权「三局两胜代裁」只覆盖普通 [需用户] 级裁量。以下五类**无论面板多数意见如何，
今夜一律不裁**，登记 BOARD 待用户裁决区（标 [需用户]＋「晨起追认队列」）：

- **安全**（隔离红线放宽、外部应用唤起面扩大、可执行文件落盘、会话/凭据使用）；
- **法律**（版权物料、爬虫产物入库边界之外的任何模糊地带）；
- **付费资产/购买控制**（购买流、付费、年龄、访问控制的任何 VUA 侧介入）；
- **产品边界**（product-boundary 语义增删、白名单准入程序变更、新产品面增设）；
- **契约冻结语义**（冻结硬前置豁免、冻结件原位修改、跳过消费测试）。

### 0.3 引据警示——两套「裁决 N」编号并存

现存两套编号：**13 项用户裁决的项号**（项 2＝M6 增设允许先模糊；项 3＝购买流不做；
项 4＝白名单外只提示＋爬虫参考；项 5＝下载落库归数据……见 wt-4/wt-5/wt-6 状态文件）
与 **BOARD U9 标题里的「裁决 4」**（＝新窗口/外部协议四分法实施细则，另一序列）。
夜间面板**必须锚定 BOARD 行号（U7/U8/U9）或受管文档版本（outline 2.0.11）引用裁决**，
不得只写「裁决 N」，防止错引。本报告一律用 BOARD 行号。

### 0.4 底线恒定项——任何选项组合都不得触碰

- 契约先行：IMP-3 冻结硬前置（Schema＋正负例向量＋至少一端消费测试＋TS 登记＋双语协议＋REGISTRY）齐备前，下载落库呈现不得合入 main（前轮报告 H-2）；
- 诚实纪律五条全效：空态即终态、失败如实、恢复不隐式续跑、mock 不出 DEV（leak 指纹扫描）、无真机证据不宣称端到端；
- 隔离红线一条不动：sandbox／contextIsIsolation（原文 contextIsolation）／无 preload／独立 partition／能力面只含标准 Web API；
- 爬虫 html 与用户本地路径**永不入库**；凭据/Cookie 永不中转；不绕过购买/年龄/访问控制。

### 0.5 留档要求

每次代裁：记条目号（本报告编号）、表决 2:1 的三方 verdict 与理由摘要、采纳结果、
影响面（文件/命令/提交），写入当夜 collab/reviews/ 或 BOARD 追认队列，晨起供用户追认。
「留晨起」项同样登记（BOARD 待用户裁决区），并注明今夜采取的保守 interim 处置。

   伪协议无条件拒（U9(2)(3)）＋手势判定（U9(4)，A-5）。
4. **两套「裁决 N」编号并存**（0.3 节）——建议集成在 BOARD 下次更新时加一行编号对照注记，
   消除夜间误引风险。

## 4. 晨起追认清单模板（面板留档用）

每夜每裁一行：`日期时间｜条目号｜问题一句话｜三实例 verdict（如 通过/通过/否决）｜采纳
结果与理由一句话｜影响面（文件/命令/提交）｜是否需用户改判`。「留晨起」项同格式登记于
BOARD 待用户裁决区并标 [需用户]＋interim 保守处置。用户晨起逐条追认或改判；改判不视为
面板过错（机制即设计为可纠正）。

审阅者结语：今夜真正的压力点不是"缺裁决"，而是"把不该裁的当成可裁的"——冲刺授权最容易被
引用来豁免它从未覆盖的底线（B-1），下载失败最容易被顺手放域消音（D-4），W25 前置齐备最容
易被当成开窗授权（F-1）。本清单把这四处与 U9 细则的六处模糊全部预置了保守默认值；面板的
自由裁量空间在细节，不在底线。
