# 工作节拍命令（TICK v1.4）

> 用法：把下面「命令正文」代码块**原样**定时发送给六个常驻进程（六进程文本完全相同）。
> 定时配置：**工作时段内每 20 分钟一次**；建议错峰：集成 :00、桌面 :05、核心 :10、
> 产线 :15、数据 :20、环境 :25（分钟偏移，仅建议）。非工作时段不发。
> 进程首次启动不用本命令——用 `collab/roles/<角色>.md` 入职提示词。
> 时间纪律（23:00–08:30 工作 / 08:30–09:30 收尾 / 09:30 后强制截断）与升级规则
> （解决不了→升级用户，不硬撑）都写在命令正文里，进程自己执行，发送方不用关心。

## 命令正文

```text
工作节拍。全程用中文思考与记录，按 AGENTS.md 与 collab/README.md 的规则执行一轮：
0. 先运行 `date` 查看当前本地时间，确定运行模式：
   - 23:00–次日 08:30（工作时段）：正常执行下列全部步骤，允许开新切片；
   - 08:30–09:30（收尾时段）：禁止开新切片，只把手头能安全收尾的提交做完并完成第 5 步；
   - 其它时间（非工作时段）：强制截断——未提交改动以 wip: 前缀提交到本树 slot 分支
     （wip 提交永不合并 main，下一工作时段继续或回滚），更新状态文件后立即退出，
     不执行第 1–4 步；
1. 运行 `pnpm collab:brief`，先处理【① 注意】中指向本角色的阻塞与留言（在相关 proposal
   内联线程回复，或更新本树状态文件）；
2. 领取任务，优先级从高到低：本树状态文件中自己的在途事项 → collab/BOARD.md 开放问题中
   本角色行 → docs/development-outline_ZH.md「当前窗口」本角色行 → 下一个未关闭 M 门的
   任务分解表中本角色行；标有 [需用户] 的条目跳过（等用户裁决，不得代决）；
   全部为空则直接跳到第 5 步；
3. 开工：切片完整性优先——你在本树同一分支内完成该切片的全部层（schema/Rust/TS/测试/
   文档同批）；需要他角色输入时在 proposal/留言写清后继续，不等待、不共写分支；
   日常非切片改动仍不得越所有权域；
4. 提交纪律：工作在本树 slot/wt-* 分支上提交（开工前先合并 main 最新）；相关测试全绿才
   提交；合并回 main 前先跑 `pnpm collab:brief` 确认分叉与失鲜状况，合并用 --no-ff；
   仅 collab/ 变化的合并免全量测试；跨角色所有权域的切片合并由集成角色验收后执行；
5. 固化（防空转反馈环）：状态文件只在内容实质变化时更新——baseline 追平不算实质变化；
   空转轮（无新交付、无新阻塞、无新留言）不提交、不同步 main、不更新状态文件；
6. 收尾：无事可做、等待他角色时，如实写进状态文件后退出待命，不编造工作。
   解决不了的问题必须升级而非硬撑（防"臭皮匠共识"）：同一问题两轮 tick 无实质进展、
   需要猜测才能继续、proposal 两轮无收敛、或涉及安全/法律/付费资产/产品边界时，
   把问题、已尝试路径、卡点、待裁决选项写入 collab/BOARD.md「待用户裁决」区并标
   [需用户]，然后退出该项工作。宁可停工，不得猜测、不得降低标准（跳测试、放宽校验、
   收窄范围而不声明）、不得用多进程互相引用制造共识假象。
```
