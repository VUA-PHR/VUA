# 工作节拍命令（TICK v1.8）

> Integration override (2026-09-22): read [protected-main policy](PROTECTED_MAIN.md) before any merge or push. All main changes, including bookkeeping, use an isolated branch and GitHub PR; canonical main only fetches and fast-forwards. This supersedes older direct-main instructions below.

> 用法：把下面「命令正文」代码块**原样**定时发送给六个常驻进程（六进程文本完全相同）。
> 定时配置：**工作时段内每 20 分钟一次**；派发并发上限 2，角色轮转次序
> 集成→核心→产线→桌面→数据→环境，拍间 ≥5 分钟（分钟偏移按此次序分布，仅建议；
> 细则见下「操作者窗口修订」节）。非工作时段不发。
> 进程首次启动不用本命令——用 `collab/roles/<角色>.md` 入职提示词。
> 时间纪律（23:00–08:40 工作 / 08:40–09:30 收尾 / 09:30 后强制截断）与升级规则
> （解决不了→升级用户，不硬撑）都写在命令正文里，进程自己执行，发送方不用关心。

## 操作者窗口修订（v1.8 入册）

> 此前仅存在于 23:00 定时任务提示词，2026-09-26 随 TICK v1.8 入册。第 3 条为命令
> 正文第 2 步「全空跳第 5 步」的窗口期修订：空队列先反向审查，再固化待命。

1. **双触发锁**：开窗先查 `collab/.window-lock`——mtime <40 分钟 fresh＝他者在跑，
   即退出不重复开窗；本窗口启动时写锁、收口删除。
2. **派发并发上限 2**＋角色轮转次序（集成→核心→产线→桌面→数据→环境）＋拍间
   ≥5 分钟；与 `collab/LAUNCH.md`「派发前在途核查」（同角色零在途才派发）并存。
3. **空队列不空转**：领取链全空时，各座对本所有权域做自我反向审查（先例：集成
   第 148/191 批），不造壳提交。
4. **用户侧任务（W25 走查等）不阻塞开发，用户消息永远优先。**

## 命令正文

```text
工作节拍。全程用中文记录，按 AGENTS.md 与 collab/README.md 的规则执行一轮：
0. 先运行 `date` 确定运行模式：23:00–08:40 正常；08:40–09:30 禁开新切片只安全收尾；其它时间 wip: 提交后立即退出；
1. `pnpm collab:brief` 处理指向本角色的阻塞与留言；
2. 领取任务：本树在途 → BOARD 开放问题本角色行 → collab/proposals 待办（事实队列）——[需用户] 跳过；全空跳第 5 步；
3. 开工：切片完整性优先（同分支全部层同批）；需他角色输入写清后继续；不越所有权域；
4. 提交纪律：slot/wt-* 分支（先合并 main）；测试全绿才提交；合并 main 前 collab:brief，--no-ff；跨角色切片集成验收合并；
5. 固化：实质变化才更新状态文件；空转轮不提交；
6. 收尾：无事如实待命；解决不了升级 [需用户]；宁可停工不猜测不降标不造共识。
```
