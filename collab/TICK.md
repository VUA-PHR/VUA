# 工作节拍命令（TICK v1）

> 用法：把下面「命令正文」代码块**原样**定时发送给六个常驻进程（六进程文本完全相同）。
> 建议错峰发送以降低 main 合并与锁竞争：集成 :00、桌面 :07、核心 :14、产线 :21、数据 :28、
> 环境 :35（分钟偏移，仅建议）。
> 进程首次启动不用本命令——用 `collab/roles/<角色>.md` 入职提示词。

## 命令正文

```text
工作节拍。按 AGENTS.md 与 collab/README.md 的规则执行一轮，全程用中文思考与记录：
1. 运行 `pnpm collab:brief`，先处理【① 注意】中指向本角色的阻塞与留言（在相关 proposal
   内联线程回复，或更新本树状态文件）；
2. 领取任务，优先级从高到低：本树状态文件中自己的在途事项 → collab/BOARD.md 开放问题中
   本角色行 → docs/development-outline_ZH.md「当前窗口」本角色行 → 下一个未关闭 M 门的
   任务分解表中本角色行；全部为空则直接跳到第 5 步；
3. 开工：任务在本角色所有权域内的部分由你独立完成；跨域部分需要他角色配合时，在
   proposal/留言写清需求后继续做你域内部分——不替他角色改其所有权文件，不与他树共写分支；
4. 提交纪律：工作在本树 slot/wt-* 分支上提交（开工前先合并 main 最新）；相关测试全绿才
   提交；合并回 main 前先跑 `pnpm collab:brief` 确认分叉与失鲜状况，合并用 --no-ff；
   改动超出本角色所有权域的合并留给集成角色执行；
5. 固化：更新本树 collab/state/wt-*.md（baseline_commit 推到本分支尖、交付、阻塞、留言），
   提交；
6. 无事可做、等待他角色、或需用户裁决时：如实写进状态文件后退出待命，不编造工作；
   若在限时运行窗口内工作（如夜间免费额度），窗口剩余不足 30 分钟时不开新切片，
   只做固化与提交。
```
