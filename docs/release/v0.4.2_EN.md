# VUA v0.4.2 Release Notes

[English](v0.4.2_EN.md) | [简体中文](v0.4.2_ZH.md)

> Date: 2026-09-04
> Type: M2 gate (v0.4.2): application contract and the persistent task loop
> Baseline: v0.4.1

## Summary

The M2 gate delivers: the application contract frozen as stable Gateway v1, Electron switched
from an in-process Mock to a **supervised real Provider process** (SQLite authoritative task
state), and the Renderer gaining a typed Gateway client plus the full presentation-layer asset
set. All five integration deliverables (reload, multi-window, temporary disconnection, process
shutdown, restart recovery) passed acceptance against the real two ends.

## Application contract and Gateway v1 (frozen)

- The application contract v0.1 was **frozen as stable Gateway v1** (2026-09-04) after the
  B1/F2 real integration acceptance; breaking changes now require a version bump; new methods
  follow the "Versioning and evolution" registration;
- Method surface: `application.getSnapshot`, `task.list`, `task.get`,
  `task.requestCancellation`, `environment.getSnapshot`, `task.startDemo` (capability-gated
  demonstration channel; leaves the production capability table once F3 lands); the seven
  `production.*` methods are registered separately as the B3/F3 candidate draft;
- Kernel: full six-method routing; application errors pass through with `code=application`
  carrying the contract `AppErrorV01` verbatim; typed event broadcast reaches local-origin
  windows only;
- Presentation projections must be total (a new contract state without a projection fails
  tests).

## Supervised Provider and persistent tasks (B2 landed)

- Electron Main starts the `vua-orchestrator-provider` process via
  `SupervisedProcessProviderV01` (frame protocol v0.1, single-instance lock, Windows process
  tree containment, SQLite authoritative task state);
- The Rust Provider host serves all B1 methods: operation-level capability table, environment
  presence-fact snapshot (detection probes arrive with F6/B6), demo tasks (deterministic state
  progression, commandId idempotency);
- Restart recovery: leftover non-terminal tasks keep their last real state marked
  `inspect_required`, presented honestly by the presentation layer;
- Process shutdown: `prepareShutdown` before quit; tasks still blocking past the timeout are
  force-terminated by the Kernel with a user decision ID.

## Presentation layer (F2 and legacy asset restoration)

- The legacy KIMI presentation assets completed migration: 16 feature areas, four-locale
  i18n, three WebGL scenes, the full Design Token set and base primitives;
- F2: typed Gateway client (explicit unavailable / request_rejected / application failures),
  live task-center and environment-snapshot ports, honest disconnection states;
- Quality gates ×5 wired into `pnpm check`: boundary, i18n completeness, table alignment,
  contrast, fixture leakage.

## Notable fixes

- **Sandbox preload bridge fix**: sandboxed preloads cannot require workspace packages — the
  built preload failed silently so `window.vua` was never injected (the renderer had been
  running degraded without any bridge); fixed and verified through the real chain;
- **Demo task progression deadlock fix**: a cancellation arriving while the task was in
  `queued`/`preparing` left it stuck in `preparing` forever; cancellation now only converts
  the step after `running` into the terminal state and never blocks progression.

## Verification

- 302 TypeScript tests, 48 Rust tests (6 real-asset manual tests ignored by design), strict
  Clippy clean;
- Production build and all quality gates pass: boundary, i18n completeness, table alignment,
  contrast, zero fixture leakage;
- The M2 five-deliverable smoke passed with 11 checks green (evidence kept locally, not
  committed);
- A TS↔Rust end-to-end test verifies handshake, capabilities, the full demo task lifecycle,
  and safe shutdown against the real binary.

## Known boundaries

- The `production.*` use-case surface is the B3/F3 candidate draft, frozen with the first
  production use-case implementation;
- Environment detection probes and the detection execution command belong to F6/B6; remote
  browsing belongs to F4;
- A fresh clone needs one root `pnpm build` first (topological build of the Provider dist and
  the Rust binary).
