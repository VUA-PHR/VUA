# VUA v0.5.0 Release Notes

[English](v0.5.0_EN.md) | [简体中文](v0.5.0_ZH.md)

> Date: 2026-09-07
> Type: M3 gate (v0.5.0): first Electron—Orchestrator—Unity vertical delivery
> Baseline: v0.4.2

## Summary

The M3 gate delivers the first production vertical use case spanning Electron, the Rust
Orchestrator, and real Unity `2022.3.22f1`: a synthetic Avatar plus one clothing item,
through both material intakes — direct `.unitypackage` import and local VPM build/install —
passing the full Inspect-to-Recover lifecycle matrix. The I-1 real-machine matrix passed
**16/16 cells on real Unity** (success, boundary cancel, source drift, Bridge timeout,
fingerprint/staging verification rejects, rollback failure, idempotent replay). The same
gate landed the six-crate architecture split, the frame-protocol handshake Schema freeze,
the full warehouse three-command chain, and a three-round user walkthrough closure.

## Vertical delivery and the I-1 real-machine matrix

- Both material intakes run end to end: the direct-import path (P1) and the local VPM
  build/install path (P2: staging template + Bridge materialize + deterministic publish +
  real `vrc-get` install + target validation);
- 16/16 cells of real-machine evidence (eight lifecycle scenarios × two paths): boundary
  cancel (`cancelled` code + receipt), source drift (`source_drift` before first write),
  Bridge timeout (1s budget + `Restored`), stale-fingerprint and staging-manifest tampering
  triggering a **real C# verification reject**, snapshot-loss injection
  (`RollbackOutcome::Failed` + `rollback_failed` receipt), replay at 351µs with zero Unity;
- Real-machine evidence is kept on the developer machine under `_local_w1/` (25 items,
  all 16 cells covered, including calibration-round logs); integration acceptance added
  an evidence-manifest check and one independent cell re-run;
- Execution discipline: tests never delete source directories; staging templates must be
  seeded with the SDK (NDMF compile dependency) — both are documented in
  `material_exec_real.rs` comments.

## Contract freezes (new in this gate)

- **production-use-case v0.1 frozen** (2026-09-07, at M3 acceptance): all four freeze
  preconditions delivered and verified (seven-method Schemas, shared fixture vectors,
  bidirectional contract tests, the I-1 real-machine matrix). The 2026-09-06 withdrawal
  history is preserved in the protocol document status block (honesty discipline);
- **amf-production v0.2** (Schema + eight vectors) frozen with M3 acceptance;
- **provider-process v0.2**: the handshake frame face Schema is frozen
  (`provider-frame-v0.1`, 11 two-side vectors); handshake request `payload` must be
  `null`, and the response must carry the `downloadIngest` capability bit (root-cause fix
  for the F4-4 bit drift). **Frame-face behavior change**: legacy handshake frames are
  rejected with `protocol_error`;
- **bdl-commands v0.1 → v0.1.1**: the warehouse three-command vocabulary
  (setArtifactMode / generateVpm / deleteOriginals) and protocol frozen, including
  application-face code annotations.

## Architecture

- **Six-crate split landed**: `orchestrator` (core), `bdl-store`, `unity-bridge`,
  `provider-host`, `acquisition`, `project-manager`;
- **environment_managers moved into `project-manager`** (proposal 004, option 3): port
  contract types stay in the core (`VccSettingsReader` et al.), the wire face is unchanged,
  and the parse-order invariant lives in exactly one place in the core.

## Walkthrough closure and user rulings

- Three user walkthrough rounds closed: initial (partial pass) → re-verify → final pass
  (R1–R5); results archived under `_local_m4/v0.4.2/`;
- Fixes: task titles bound to entry entities, full i18n sweep (including mixed Chinese in
  ko), details moved to a right-side flexible region with adaptive card-wall columns,
  DEV scene-bar collapse, notification DOM ghost and ✕ icon semantics;
- **Accepted semantic/UX rulings (slated for M4; truthfully declared in this release)**:
  warehouse layout rework (adaptive columns + right-side details region); the full
  experimental-settings form (two-level options: generate VPM as replacement + delete
  original after generation, shipping with the bdl-commands v0.2 upgrade). Already in this
  build: default to the original `.unitypackage`, write-command entries withdrawn from
  default presentation with a gated entry (Settings-Experimental), task center turned into
  a notification center (terminal states hidden by default + a "show completed" switch +
  per-item clear — clearing only hides the presentation; authoritative task facts remain
  queryable);
- Product boundary synced: `product-boundary` 1.1.0 adds the material-entry semantics
  clause.

## Known observations (truthful)

- **#7 flaky failures**: both cases are named and root-caused (ph_010 test-side race
  moved to polling; the runtime Completed publish moved inside the tasks lock). The
  residual low-frequency flake did not reproduce under stress runs (18 consecutive green
  runs) and has no sample; it stays under observation and reopens the procedure on
  recurrence.

## Quality

- Rust: `cargo test --workspace` all green (44+ suites), `cargo clippy --all-targets`
  zero warnings;
- TypeScript: desktop full check chain green (47 files, 385 tests), production-build
  leak fingerprint scan zero hits;
- I-1 real-machine matrix 16/16 (real Unity `2022.3.22f1`, global edition).

## Upgrade and migration

- No user data migration from v0.4.2; the Provider frame-protocol handshake change is
  covered by the synchronized two-side upgrade (`provider-process` 0.1→0.2, see the
  protocol document changelog).
