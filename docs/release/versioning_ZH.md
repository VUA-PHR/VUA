## 产品版本

VUA 产品发行遵循 [Semantic Versioning 2.0.0](https://semver.org/spec/v2.0.0.html)：
`MAJOR.MINOR.PATCH`，并可附加预发布标识和构建元数据。

- Git 发行 Tag 使用 `vMAJOR.MINOR.PATCH`；`v` 只是 Tag 前缀，不属于 SemVer 值。
- `0.y.z` 表示初始开发期。公开契约仍可能发生不兼容变化，但每次破坏性变化必须在发行说明中
  明确记录，并同步修改所属协议、Schema 或迁移规则。
- 在 `0.x` 内，VUA 约定 Patch 用于兼容性修复，Minor 用于计划阶段、新能力或明确记录的契约变化。
- `1.0.0` 定义首个稳定公开产品 API 与兼容性承诺。
- 已发布 Tag 和制品不可修改；任何变化都必须发布新版本。

## Beta 与发行候选

`0.10.0` 和 `0.11.0` 是 Major Zero 开发期内的正常 SemVer。VUA 可以把发行渠道称为 “Beta 1”
和 “Beta 2”，但这是项目生命周期标签，不是 SemVer 预发布标识。若要验证确切的 `1.0.0` 契约，
可以使用 `1.0.0-rc.1`，随后发布 `1.0.0`；预发布版本的优先级低于对应正式版本。

计划顺序：

```text
0.9.0       功能路径完成
0.10.0      Beta 1：功能与公开契约冻结
0.11.0      Beta 2：恢复、安全、升级、打包与发行验证
1.0.0-rc.1  可选的 1.0 契约发行候选
1.0.0       首个稳定版
```

## 独立版本对象

产品 SemVer 不取代协议或存储格式版本：

| 版本对象 | 规则 |
| --- | --- |
| 桌面产品与安装包 | 使用同一产品 SemVer 和唯一发行版本来源 |
| Git Tag | `v` 加完全一致的产品 SemVer |
| Orchestrator Provider | 与对应桌面版共同构建、分发，并报告传输、构建、协议和产品兼容性 |
| Unity Bridge | 拥有机器可判定的协议/包版本，显式声明兼容范围 |
| Gateway 与社区插件协议 | 拥有机器可判定的契约版本，不能只由产品 SemVer 猜测兼容性 |
| Recipe、Build Record、持久化 Schema | 拥有格式/Schema 版本以及迁移或拒绝行为 |
| 私有 Workspace 包 | 不自动构成公开 API；版本服从发行工具政策 |
| 第三方实现依赖 | 在 lockfile/依赖清单精确记录，不作为 VUA 版本展示 |

发行流水线负责在桌面 Manifest、Provider 元数据、安装包、诊断输出和发行制品之间生成或校验
产品版本。多处手工维护的重复版本字符串不具有权威性。

## 兼容性与沟通

- 每次公开发行都有 Release Notes；`0.x` 破坏性变化必须指出受影响 API/格式以及迁移或重置方式。
- 当用户或社区开发者需要迁移窗口时，移除前先发布弃用说明。
- `+sha.<commit>` 等构建元数据可标识 CI 制品，但不影响版本优先级或兼容性。
- `pre-alpha`、`alpha`、`beta`、`stable` 等产品阶段名不能替代数字版本。
