# VUA v0.4.2 发行说明


> 日期：2026-09-04
> 类型：M2 门（v0.4.2）：应用契约与持久任务闭环
> 基线：v0.4.1

## 概要

M2 门交付：应用契约冻结为稳定 Gateway v1，Electron 由进程内 Mock 切换为**受监督真实
Provider 进程**（SQLite 权威任务状态），Renderer 获得类型化 Gateway 客户端与全量表现层
资产。五项整合交付（重载、多窗口、暂时断连、进程关闭、重启恢复）全部通过真实两端验收。

## 应用契约与 Gateway v1（冻结）

- 应用契约 v0.1 经 B1/F2 真实整合验收后**冻结为稳定 Gateway v1**（2026-09-04）；
  破坏性变更自此必须升版本号；新增方法按"版本与演进"登记；
- 方法面：`application.getSnapshot`、`task.list`、`task.get`、`task.requestCancellation`、
  `environment.getSnapshot`、`task.startDemo`（能力门控演示通道，F3 落地后移出生产能力表）；
  `production.*` 七方法以 B3/F3 候选草案另行登记；
- Kernel：Gateway 六方法全路由；应用错误以 `code=application` 携带契约 `AppErrorV01` 原值
  透传；类型化事件广播仅达本地来源窗口；
- 表现层投射必须穷尽（契约新增状态未覆盖即测试失败）。

## 受监督 Provider 与持久任务（B2 落地）

- Electron Main 经 `SupervisedProcessProviderV01` 启动 `vua-orchestrator-provider`
  进程（帧协议 v0.1、单实例锁、Windows 进程树遏制、SQLite 权威任务状态）；
- Rust Provider 宿主提供 B1 全部方法：操作级能力表、环境在场事实快照（检测探针随
  F6/B6 接入）、演示任务（确定性状态推进、commandId 幂等）；
- 重启恢复：遗留非终态任务保留最后真实状态并标注 `inspect_required`，表现层如实呈现；
- 进程关闭：退出前 `prepareShutdown`，超时阻塞任务由 Kernel 以用户决定 ID 强制终止。

## 表现层（F2 及旧资产恢复）

- 旧 KIMI 表现层资产完成迁移：16 个功能区页面、四语言 i18n、WebGL 三场景、
  完整 Design Token 与基础原语；
- F2：类型化 Gateway client（unavailable / request_rejected / application 三类失败
  显式区分）、任务中心与环境快照 live 端口、断连诚实态；
- 质量门 ×5 接入 `pnpm check`：边界、i18n 完整性、多表一致、对比度、fixture 泄漏。

## 关键修复

- **沙箱 preload 桥接修复**：沙箱 preload 不允许 require 工作区包，此前 preload 静默
  失败导致 `window.vua` 从未被注入（渲染层一直无桥接降级运行）；修复后经真实链路验证；
- **演示任务推进死锁修复**：取消请求在 `queued/preparing` 阶段到达时任务曾永久停在
  `preparing`；取消现只转换 `running` 之后的去向，不阻塞前进。

## 验证

- TypeScript 302 项、Rust 48 项（6 项真实素材人工测试按设计忽略）、Clippy 严格通过；
- 生产构建、边界、i18n 完整性、多表一致、对比度、fixture 零泄漏质量门全部通过；
- M2 五项交付冒烟 11 项检查全绿（证据本地保留，不入库）；
- TS↔Rust 端到端测试对真实二进制验证握手、能力表、演示任务全链路与安全关闭。

## 已知边界

- `production.*` 用例面为 B3/F3 候选草案，随首个生产用例实现冻结；
- 环境检测探针与检测执行命令属 F6/B6；远程浏览属 F4；
- 全新克隆需先执行一次根 `pnpm build`（拓扑序构建 Provider dist 与 Rust 二进制）。
