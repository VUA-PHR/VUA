## Summary

The M4 gate delivers the Warehouse, asset-acquisition, and BDL chain: the catalog
observation pipeline (service face + write side + consumer surfacing), bdl-commands v0.2
global default mode, the warehouse layout rework, the full Settings-Experimental form
(converged to the global-toggle form across two user walkthrough rounds), and the
design-standard sync. Three user rulings land in the same gate: the repo-wide VPM
terminology fix, the proposal 008 ruling (path a), and the product-boundary 1.2.0
read-only compatibility with externally managed projects.

## Settings-Experimental: converged across two walkthrough rounds (W15)

- The first walkthrough **failed** (an interaction-form redo, not a defect batch): the
  user sketch is the spec authority — a global-toggle form replaced the two-option form
  (rework 4fb6411);
- The **second-round re-review passed**, with two fix items landed (2fa260d):
  ① trigger-timing semantics = **automatic generation at material import** (not wired in
  this version, honestly labeled in the UI; generation is still started manually by the
  user from the warehouse entry; the import-time hook and orchestration semantics land
  with the M5 wiring); ② terminology "generate VPM replacement" → "generate a VPM package
  replacement";
- Form: title + subtitle + yellow warning strip + two toggle rows — "generate a VPM
  package replacement" as a global toggle (writes `warehouse.setGlobalDefaultMode`) +
  "delete original material after generation" as a red danger toggle (usable only after
  the main toggle is on; enabling requires the danger confirmation dialog; **currently an
  unwired preference, honestly labeled**); no per-entry selector.

## Proposal 008 ruling (path a)

The protocol face of "delete original material after generation" was proposed by Desktop,
stance-aligned by Data and Core, and **accepted as path a** by the Integration ruling: the
toggle = a desktop local preference; after the generate task's Done receipt the desktop
calls the existing entry-level `warehouse.deleteOriginals` **entry by entry** (each an
independently audited task). Zero protocol extension; bdl-commands v0.2 stays frozen; the
invariants (per-entry deletion, independent audit receipts, no weakening of danger
confirmation) bind the whole case; the wiring slice goes to the M5 first batch. Path b
(a task-spec flag upgrading to v0.3) is kept in reserve; path c (a bulk-delete command)
is rejected.

## Terminology ruling and product boundary

- **Hard terminology ruling (repo-wide)**: VPM = VRChat Package Manager (the manager);
  VPM package = the managed package. Managed documents (product-boundary 1.1.1 /
  outline 2.0.6), the in-app four-language i18n, and comments are fixed; frozen protocol
  documents are not retro-edited (fixed when they upgrade);
- **product-boundary 1.2.0 (U3 user ruling)**: **read-only compatibility** with
  ALCOM/VCC-managed projects, whose only write path is the user-initiated "import as a
  VUA-managed copy" (five-point spec); write capability is uniformly false within the
  `1.0.x` boundary and may only open later via a new user ruling; 1.2.1 clarifies the
  generation trigger timing (at material import).
