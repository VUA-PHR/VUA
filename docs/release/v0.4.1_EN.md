# VUA v0.4.1 release notes

[English](v0.4.1_EN.md) | [简体中文](v0.4.1_ZH.md)

> Status: M1 pre-alpha development release
> Release date: 2026-09-04
> Product version: `0.4.1`

## Delivered

- Electron Main starts a controlled in-process Mock Provider when the app becomes ready and reaches
  the application core only through the versioned `OrchestratorProviderV01` surface.
- Desktop Gateway v1 validates sender, size, and envelope before mapping `app.snapshot` to
  `application.getSnapshot`; desktop capability values are derived from the Provider's operation-level
  capability report.
- Main retains bootstrap, lifecycle, and routing responsibilities while application semantics remain
  behind the Provider/Orchestrator boundary.
- A real Electron remote-permission smoke now has a synthetic `127.0.0.1` page request notifications,
  geolocation, and media access through an isolated Session. All are denied; the page has no
  `window.vua` and cannot invoke the Gateway; application-window navigation to the remote origin is
  blocked; HTTP(S) `window.open` reaches the Shell boundary without creating an Electron window.

## Contract and compatibility

- Desktop Gateway remains v1, with `app.snapshot` as the only M1 public method.
- Application Contract remains `0.1`; this release adds a real consumer without changing the wire shape.
- The controlled M1 Provider is an in-process test implementation. B2 can replace it with the supervised
  process Provider without changing Renderer or Desktop Gateway call sites.

## Verification and evidence

- Workspace TypeScript checks, unit tests, and production builds pass.
- Electron Main, Preload, and Renderer lifecycle smoke passes.
- Remote-permission smoke command: `pnpm --filter @vua/desktop smoke:remote-permissions`.
- Local structured evidence: `_local_m1/v0.4.1/remote-permissions-smoke.json`.
- Local raw log: `_local_m1/v0.4.1/remote-permissions-smoke.log`.

`.gitignore` excludes `_local_m1/`. Evidence and raw logs remain on the acceptance machine and are not
part of the repository or release artifacts.

## Current limitations

- The M1 Provider does not host production tasks; task availability follows its capability report.
- Supervised-process hosting, SQLite restart recovery, and the complete task Gateway belong to M2/B2.
- This release does not establish stable-version compatibility commitments.
