# VPM 素材包 Spike 封口记录

日期：2026-09-03
状态：B3 前置实现证据，不是公开发布能力

## 结论

VUA 可以在保持来源 `.unitypackage` 不变的前提下，在隔离的 Unity `2022.3.22f1`
暂存项目中生成 `local-reusable` VPM 包，再通过 VUA 的 `vrc-get` 库适配器安装到全新验证项目。
直接复制到 `Packages/` 不再作为最终安装证据。

本 Spike 不提前 B6：这里只增加本地包注册、完整变更预览、摘要绑定和应用所需的最小切片；
ALCOM/VCC 项目兼容、仓库和通用环境管理仍归 B6。

## 固定边界

- 包创建、包安装和公开发布是三个用例；本阶段没有发布能力。
- 用户只看到继承来源文件夹的名称；重名使用 `名称 (2)`、`名称 (3)`。VUA 在本地身份记录中
  持久化合法机器 ID，用户不填写也不看到该 ID。
- 依赖必须显式进入生成清单。缺少依赖时，`vrc-get` 预览拒绝安装，不能通过删除依赖声明绕过。
- 来源中的 GUID、`.meta` 和相对层级保留；硬编码 `Assets/` 路径只报告，不做无类型依据的改写。
- 许可证证据记录只支持本地用途判断；`local-reusable` 的成功不等于获得再发布许可。
- Unity Package Manager 发现包并加载一个指定资源只证明 `minimum_structure`，不证明 Avatar、衣装、
  材质、动画或 Modular Avatar 语义正确。

## 可执行输入决议

Unity 启动前扫描 C#、程序集、原生插件、`Editor` 和构建入口。一个待执行批次只作一次决议：

1. 创建项目快照并继续；
2. 不创建新快照继续，可仅在当前会话记住；
3. 取消。

决议绑定来源摘要和风险文件清单。未决议时返回
`vua.vpm_spike.risk_decision_required`，且不创建 Unity 暂存项目。VUA 不声称快照能撤销项目外副作用。

## 进程与恢复

每次外部调用有正数超时、独立退出码、取消状态和有限输出。Windows 上每次调用进入独立 Job Object；
超时、取消以及主进程退出后都会收束该调用留下的进程树并报告 `processTreeClean`。

输出先写入运行目录的 `work` 区，只有 `vrc-get` 安装和 Unity 最小验证成功后才原子发布。没有终态结果的
运行可被恢复命令移动到同级隔离目录，原运行名随后可以安全重试；已经完成的运行不会被移动。

机器结果遵循 `schemas/vpm-package-spike/v0.1/result.schema.json`，错误判断使用稳定结果码而不是日志文本。

## 本地证据

- 同一 Unity 导出的合成输入在两个全新运行目录完成转换、`vrc-get` 安装和 Unity 验证；规范化清单、
  包树和确定性归档摘要均一致，来源执行前后未变化。
- 一件开发者合法取得的衣装在两个全新运行目录重复通过；验证项目来自装有 VRChat SDK、lilToon 和
  Modular Avatar 的只读基线副本，清单显式声明 lilToon 依赖。私有素材、路径、项目、日志和输出未进入 Git。
- Unity 导出的带 Editor 脚本合成输入在未决议时于 Unity 启动前拒绝；选择“快照并继续”后完成实际安装
  与最小加载验证。
- 缺失声明依赖的运行在 `vrc-get` 预览阶段失败，未发布包；其未完成目录已成功隔离并允许同名重试。
- 人工截图确认全新验证项目在 Unity `2022.3.22f1` 中显示已安装包、`Runtime` 层级和衣装 Prefab
  缩略图。截图含私有素材，仅留在本地证据目录；该观察仍只计为 `minimum_structure`，不提升为语义正确。
