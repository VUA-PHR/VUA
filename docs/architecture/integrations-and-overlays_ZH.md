## 信任类别

分类依据是数据接触与权威；环境、追踪、优化、可访问性和外观统一作为条目正文中的用途说明。

| 类别 | 运行/存在位置 | VUA 访问 | 故障收敛 |
| --- | --- | --- | --- |
| Core | 直接构建进 VUA 的可信产品行为 | 通过所属用例和端口使用内部应用服务 | 对应能力拒绝或降级；持久任务仍可恢复 |
| Plugin | 由公开版本化能力协议定义的独立社区扩展宿主 | 显式授权定义其全部权限 | 故障限制在插件及其获批任务内 |
| External | 独立应用、Unity Package、运行时或设备服务 | 保持独立权威；VUA 侧适配器另行归类为 Core 或 Plugin | 外部能力降级并保留人工路径 |

Kernel 与本地 UI 是稳定宿主表面。Core 目录条目通过所属应用契约访问数据库与私有状态，目录分类
不形成运行时模块系统。
[工具目录](../tool-catalog/README.md)保存分类与证据，各归属评审分别批准产品范围、协议权威、
信任、分发与执行。

## 统一适配器模型

外部工具通过领域端口后的可替换适配器连接。每个集成登记：

```text
上游与许可证
→ 用户问题与能力
→ 发现方式
→ 可选托管 / 外部连接模式
→ 支持版本与数据边界
→ 安装、更新、启动和卸载所有者
→ 权限、凭据与日志
→ 失败降级和人工路径
```

优先使用官方 API、CLI、OSC、配置或导入/导出格式。禁止依赖未授权私有数据库、复制登录会话、
反射内部实现或以 UI 自动化伪装稳定接口。

## 外部集成双模式

- **可选托管**：许可证允许时，由 VUA 下载或调用官方分发、校验、安装、更新、启动和监控；
- **外部连接**：发现用户独立安装的工具，通过公开边界连接，不接管其账号和内部状态。

每个模式独立报告能力；外部能力变化时，Recipe、本地项目和恢复流程保留原生路径。`1.0.0` 后
接受的方向包括通过 VRCFaceTracking 接入面捕、通过 SlimeVR
Server 与 OpenVR Space Calibrator 接入动捕，以及通过经审计公开边界接入 Avatar 优化器。项目
管理、AMF 来源和 Overlay 适配器服从同一向内依赖方向，但保持各自产品所有权。

## 环境修改与 EAC 恢复

环境工具先执行只读侦测，返回证据、就绪结论和人工路径。下载、启动安装器、写入、提权和进程动作
都必须成为明确的计划步骤，经过用户确认并在执行后复检。

EAC 冲突侦测默认只读。终止 EAC 或 VRChat 相关残留进程属于默认关闭、实验性、高风险的末级选项，
每次执行前必须提示可能出现账号异常并再次确认。它只能针对允许清单中的用户态残留进程，并在执行
前核验、展示名称、PID、路径、签名/发布者和原因；存在活跃游戏会话时拒绝执行。它不得停止服务或
内核驱动、修改 EAC/VRChat 文件或配置、注入/挂钩/隐藏进程、规避反作弊，也不得向网页、Overlay
或插件暴露终止能力。证据不明时只能诊断。

## 社区插件宿主

社区插件通过版本化协议访问稳定服务：

- Manifest 声明身份、版本、入口、兼容范围和能力；
- 宿主负责启停、超时、取消、资源预算、日志与权限；
- 插件不能直接访问主 SQLite、BDL、Electron Session、Cookie、私有实现类型或 Unity Editor 对象；
- 敏感能力逐项授权，默认拒绝；
- 协议未知或能力不足时拒绝加载，不猜测兼容；
- 初始阶段不提供托管插件市场，也不自动运行未知来源插件。

社区插件运行在独立宿主中，并使用 Manifest 获批权限。进程外、Wasm 或受信任原生插件通过单独
安全 ADR 决定。

VR 睡眠亮度、界面实时翻译、变声器和 VUA 皮肤等社区增强，只有在能力可收紧且可独立移除时才
属于此处。目录条目记录分类与证据，发布评审授予分发与信任。

目录作者声明能力和行为，不自主填写风险结论。发布前由 `vua.risk-gate/v1` 派生命中的最高等级，
拒绝未知或不完整的能力集合，并施加对应警告、确认、拒绝路径测试和安全批准。

## 项目管理的三条路径

项目管理适配器统一暴露项目发现、读取、能力检查、包计划、应用和验证端口，但三条路径的承诺不同：

| 路径 | VUA 的责任 | 兼容目标 |
| --- | --- | --- |
| VUA 包管理器 | 基于 `vrc-get` 自建并维护完整原生路径 | VUA 创建和管理的项目 |
| ALCOM 项目兼容 | 读取项目状态并在能力允许时继续管理 | ALCOM 管理的项目，而非 ALCOM 应用本身 |
| VCC 项目兼容 | 通过公开项目格式和受支持边界继续管理 | VCC 管理的项目，而非 VCC 私有实现 |

任何一条兼容路径都必须先检测项目能力、版本和锁定状态。无法证明安全写入时，适配器返回只读、
转换建议或人工交接能力，不能将“能发现项目”表述成“完全兼容”。

## Overlay 边界

桌面与 VR Overlay 共享同一教程/运行时展示状态，通过窄化 Surface Port 获取版本化快照并返回
语义动作。应用核心拥有任务与业务状态。

首个 VR 路径使用独立 SteamVR Dashboard helper 和公开 `IVROverlay`：

- 独立构建、独立进程、用户显式启动；
- 只接收显示快照，返回 `next`、`back`、`dismiss`、`open_on_desktop` 等语义动作；
- 不接收素材、Unity 项目、账号凭据或通用文件能力；
- 通信通道具有消息长度上限、版本握手、当前用户限制和进程监督；
- 未验证或不支持的运行时自动退回桌面 Overlay。

任何 Overlay 都不得注入 VRChat、挂钩 DirectX/Vulkan/OpenXR、安装影响 VRChat 的 API layer、读取
VRChat 进程内存/模块、修改 EAC 或自动确认账号、安全和上传界面。公开 OSC 输入属于不可信数据，
不能授权本地修改。
