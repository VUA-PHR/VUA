## 1. 体验定位

VUA 是面向玩家的可靠生产助手：比企业后台友好，比游戏启动器专业，比极客工具克制。它既不采用
“代码瀑布 + 高饱和霓虹”的赛博面板，也不套用 Office 式管理后台。

视觉由四层组成：

1. **Windows 桌面行为底座**：清晰焦点、稳定布局、窗口预期和可预测的控件行为；
2. **原生桌面工具质感**：以 macOS 原生工具为视觉参考，用 1px 边框、轻阴影、留白和克制层级
   组织控件；
3. **深邃工坊氛围**：近黑紫画布、低透明紫/橙环境光、玻璃层级与可降级的 WebGL 场景；
4. **任务叙事**：AMF 车间轨道与真实事件反馈，只在能解释真实工作时出现。

氛围是背景和灯光，不承载唯一信息。关闭模糊、辉光和动画后，信息、层级和操作必须完整。

## 2. 产品体验原则

### 2.1 目标先于术语

先询问用户希望得到什么结果，再逐步介绍 Unity、VPM、Armature、Shader 等必要概念。推荐项必须
说明推荐原因、影响和替代路径。

### 2.2 Recipe-first 与路径选择

AMF 的能力域仍完整覆盖 Warehouse → Recipe → Assembly → Inspection → Release 五个阶段，但
不再要求所有玩家走完一条固定大流程：生产 Wizard 按目标、设备与当前状态选择路径，只走该次
生产实际需要的阶段（0.7.19，用户裁决 2026-09-22——已接受方向，尚未实现）。完整流程覆盖
对排障与高级用户仍有价值，保留为可选路径而非必经路径；引导不替代账号认证与平台授权；
Quest 初次激活教程区分「独立运行」与「连接 PC」两条路径。

执行、等待输入、恢复和重试是 Assembly 或其他用例的任务状态，不另设 Production 用户阶段。

### 2.3 事实明确

界面必须让用户确认当前目标、对象、保存状态、任务状态、阻断原因、恢复条件和下一步。未知就是
未知；不可用就是不可用；Fixture 必须明确标记为演示数据。

### 2.4 可恢复优先

普通编辑提供撤销或明确反向操作。高影响操作在执行前说明对象、范围、耗时、磁盘影响、快照和
恢复方式。页面关闭和 Renderer 重载不能丢失已接受任务。

### 2.5 渐进式专业化

新手使用解释性向导；熟练用户使用工作台、快捷键、批量操作和高密度视图。两种入口调用相同的
应用用例，不复制领域规则。

### 2.6 内容优先

Avatar、衣装、预览、Recipe 和 Build Record 是主角。界面铬件不覆盖缩略图，不以装饰抢占内容，
也不把第三方品牌强制染成 VUA 颜色。

## 3. 平台与信息架构

### 3.1 参考标准

| 范围 | 基线 |
| --- | --- |
| Windows 窗口、焦点与常用控件 | Microsoft Fluent 2 |
| 表格、树、筛选、批量操作 | IBM Carbon 的信息结构参考，不复制其视觉皮肤 |
| 可访问性 | WCAG 2.2 AA |
| 复合控件键盘模式 | WAI-ARIA APG |
| 可用性评审 | Nielsen 十项启发式原则 |

### 3.2 应用壳

- 顶部固定五个一级 Tab：**指挥台、环境部署、游戏引导、工具合集、模型生产**；设置固定在最
  右侧。左侧承载当前区域的二级功能索引；底部任务中心按能力显示；内容区独立滚动；
- 五个一级区域对应恒定落点与四类用户目标。正式功能在进入对应一级区域后应一次点击可达；新增
  能力优先进入现有区域和侧栏分组，改变一级信息架构需另行取得产品与设计批准；
- 一级 Tab 使用 `skewX(-12deg)` 的平行四边形卡片，文字反斜回正；选中态使用下沉 1px、辖区
  色深底、描边、内阴影和底部亮边组成的“按下”物理语言；
- 窄宽度使用三级折叠梯子：完整字标与全部 Tab → 隐藏品牌副标题 → 整排 Tab 收入显示当前区域
  的折叠按钮。折叠菜单容器透明，原 Tab 控件竖排错峰飞出；键盘、焦点、外击和 reduced-motion
  行为遵循 Menu/APG 与降级规则；
- 侧栏条目保留 hover/选中“生长”视觉、右移 3px、tint 底、左侧 2px 辖区色竖条和柔光。实现
  使用 `transform: scale(...) translateX(...)` 或等价合成层方案，并预留稳定槽位；字号与 padding
  保持固定，使相邻条目和指针目标不移动；
- 自定义标题栏仍遵循 Windows 的拖动、最大化、系统菜单、缩放和窗口控制预期；
- 远程网页明确标识来源和安全边界，与本地 VUA 页面保持视觉区分，不能伪装成本地表单。

### 3.3 两类页面

**引导页**按“目标与进度 → 一个问题或结论 → 必要解释 → 返回/继续”组织。每页只要求一个主要
决定，执行前汇总完整计划。

**工作台**按“顶部目标和命令、左侧对象/筛选、中部工作区、右侧 Inspector、底部任务/诊断”组织。
面板可以按真实需要调整尺寸；对话框只用于必须立即决定或确认高影响操作的场景。

## 4. Design Token

`packages/design-system` 落地后，Token 代码是本文数值的机器可检验镜像。业务组件只使用语义
Token，不直接书写十六进制颜色、阴影或任意间距。

### 4.1 颜色

| 语义 | 深色 | 浅色 | 用途 |
| --- | --- | --- | --- |
| Canvas | `#0B0A12` | `#F6F6F9` | 应用画布 |
| Panel | `#151322` | `#FFFFFF` | 普通结构面 |
| Elevated | `#1E1B30` | `#FFFFFF` | 菜单、Dialog、浮层 |
| Strong text | `#F5F3FF` | `#191824` | 标题与正文 |
| Secondary text | `#B3B0C8` | `#565470` | 辅助信息 |
| Border | `#2E2A45` | `#DAD9E2` | 1px 分隔与控件边界 |
| VUA accent | `#A78BFA` | `#6557D2` | 环境、导航、设置与通用应用能力 |
| AMF accent | `#FF7A45` | `#BB4A10` | Warehouse、Recipe、Assembly、Inspection、Release |
| Success | `#4ADE80` | `#107C10` | 成功、通过、可用 |
| Warning | `#FDE047` | `#9C6D00` | 注意、等待确认、非阻断风险 |
| Error | `#FB7185` | `#D13438` | 失败、阻断、隔离 |
| Info | `#94A3FF` | `#5F6B8A` | 中性信息 |

- VUA 紫和 AMF 橙表达辖区、选择和主要操作，不表示成功或错误；
- 语义色全应用通用，并始终配合图标或文字；“大型红绿灯状态总览”只用于环境部署；
- 同一页面只有一个主辖区色。跨辖区总览可以同时出现低饱和紫/橙标识，但不能出现两个竞争的
  主操作色；
- 正文对比度至少 4.5:1；大字、焦点、图标和控件边界至少 3:1；高对比模式映射系统色。

### 4.2 字体

```text
"Segoe UI Variable", "Segoe UI", "Microsoft YaHei UI", sans-serif
```

| Token | 规格 | 用途 |
| --- | --- | --- |
| Caption | 400 12px/16px | 元数据与辅助信息 |
| Body | 400 14px/20px | 默认正文 |
| Title | 600 20px/28px | 页面和区块标题 |
| Display | 600 28px/36px | 少量入口页与状态结论 |

调试和结构化数据使用 `ui-monospace, "Cascadia Mono", Consolas, monospace`；版本号和计数使用
等宽数字。

### 4.3 间距、尺寸与层级

- 4px 基础网格：4 / 8 / 12 / 16 / 24 / 32；
- Compact 控件高 28–32px，Comfortable 控件高 36–40px；主要指针目标内部目标不小于 32×32px，
  WCAG 2.2 的 24×24px 只作为底线；
- 主按钮和状态芯片可使用胶囊圆角；输入、菜单 6px；卡片 10px；Dialog 和大型浮层 12px；
- 默认 1px 边框；普通面板和卡片不使用投影；只有 Elevated 浮层使用低透明轻阴影；
- 玻璃模糊只用于顶栏、侧栏、任务浮层和少量 Elevated 结构。卡片墙、表格和长列表不使用
  `backdrop-filter`；
- 工作台密度来自内容，不来自粗边框、大色块或过量装饰。

## 5. 组件标准

首批 Design System 覆盖：Button、Icon Button、Text/Number Field、Combo Box、Tabs、Menu、Dialog、
Drawer、Toast、Inline Notification、Task Item、Progress、Badge、Skeleton、Empty State、
Inspector Row、Tree、Table 和 Graph 基础原语。

每个交互组件按适用范围覆盖：Default、Hover、Pressed、Focused、Selected、Disabled、Loading、
Error、Warning、Success。

- 禁用关键动作时提供可发现原因；无法说明原因时优先保持可点并在执行前校验；
- Dialog 和浮层始终提供可见、名称明确的关闭或取消动作，不能只依赖遮罩或 `Esc`；
- 图标仅使用 16/20/24px 统一线性风格，并提供可访问名称；陌生图标必须配文字；
- Context Menu 只用于 Windows 用户预期且动作真实的对象；文本编辑保留原生编辑能力；任何右键
  动作都有按钮、键盘或详情面板替代；
- 组件不得持有 Recipe、权限、任务恢复或兼容性业务规则。

## 6. 交互与反馈

### 6.1 键盘与焦点

- `Ctrl+Z` 撤销，`Ctrl+Shift+Z` 重做，`Ctrl+S` 保存，`Ctrl+P` 打开命令面板；
- `Enter` 确认或进入，`Esc` 关闭临时界面，`F2` 重命名，`Delete` 请求删除；
- 快捷键仅在对应真实能力存在时注册，不能覆盖文本编辑或系统窗口惯例；
- Menu、Tabs、Tree、Grid、Dialog 和 Combo Box 遵循对应 APG 键盘模式；关闭浮层后焦点返回合理
  触发点；
- 拖放必须同时提供按钮或菜单入口，以及键盘可用入口。

### 6.2 保存与任务

保存状态统一为：已保存 / 有未保存修改 / 正在保存 / 保存失败。

任务状态统一为：等待中 / 准备中 / 运行中 / 等待用户输入 / 已暂停 / 已完成 / 完成但存在警告 /
失败 / 已取消。

任务由应用核心持有。任务项显示来源、当前阶段、可用动作、警告或错误，并在等待用户输入时提供
明确跳转入口。

任务中心以**通知中心**语义呈现（v0.6.2）：活动任务恒为通知；已进入终态（完成/警告完成/
失败/已取消）的任务默认不再作为通知出现；「显示已完成」开关负责历史终态任务的可达性；
「清除」动作只把该终态任务从通知呈现中移除（偏好持久化），任务权威事实仍可经任务列表与
详情面查询——清除的是通知，不是事实。失败通知必须与关闭按钮的 ✕ 图标语义区分（如圆形
叹号），不得共用同一图形。

### 6.3 等待与进度

- 动作触发的计算、检查或计划一旦显示忙碌反馈，该表现至少维持 700ms，避免闪烁；内容媒体加载
  不接最小忙碌。真实完成、安全和错误事实立即进入任务状态，700ms 只约束忙碌表现的最短可见
  时间；实现使用共享 Token/hook，不由页面各自书写定时器；
- 只有存在真实总量或时间来源时才显示确定进度；否则使用阶段文字和不确定状态；
- 同一稳定任务阶段的进度不得因乱序快照回退；如果计划失效或工作重启，明确创建新阶段或新任务，
  不用视觉“地板”掩盖事实变化；
- 骨架屏只表示内容布局正在加载，不表示后台任务、失败或等待用户输入；
- 列表重新查询优先保留旧结果并标注刷新状态，避免整页闪空。

### 6.4 错误与高影响操作

错误依次说明：发生了什么、影响哪个对象、已知原因或缺失条件、下一步、是否可重试/撤销/恢复。
错误码和技术细节放在可展开诊断中。

包、项目、Unity 和批量变更采用“Inspect → Plan → Confirm → Execute → Validate”表现。确认页显示
完整变更、冲突、移除和恢复条件；不可恢复操作要求确认精确对象和范围。

### 6.5 实验性功能呈现

实验性功能由「设置-实验性」页承载（W15 重做形态：单卡=标题+副题+黄色警示条+开关行）。规则：

- 写已冻结协议的开关（如「生成 VPM 替代」写 warehouse.setGlobalDefaultMode）是**服务端行为开关**：
  开关态以服务端读回/回执为准，呈现层不虚构状态；初值读不到时如实标注而非猜测；
- 依赖未冻结协议的开关（如「生成后删除原始素材文件」）是**未接线偏好**：恒挂「未接线」标注，
  开启仅记录意图、不触发任何服务端行为；开启必经危险确认对话框，DEV/fixture 面加注原型说明；
- 未接线偏好与危险开关的组合必须主从门控（危险开关在主开关关闭时置灰不可开）；
- 功能入口携带「实验性」/「危险」徽标；呈现层不削弱守卫，直达命令仍按版本化协议裁决；
- 破坏性动作即使在实验性入口内，也必须保持高危样式与延迟确认（§6.4/§8.1）。

## 7. 动效与资源纪律

| Token | 时长 | 用途 |
| --- | ---: | --- |
| Instant | 0ms | 降级和即时状态替换 |
| Fast | 120ms | Hover、Pressed、Focus 辅助变化 |
| Normal | 180ms | 抽屉、菜单、页面局部显隐 |
| Slow | 360ms | 卡片、模块和少量有因果关系的编排入场 |

标准编排缓动恢复为 `cubic-bezier(0.2, 0.9, 0.25, 1)`。动效只使用 opacity、transform 等不改变布局的
属性；不得通过 font-size、padding 或几何重排制造“生长”。

- `prefers-reduced-motion: reduce` 移除位移、缩放、视差和循环，只保留不超过 120ms 的透明度反馈；
- `data-effects="off"` 关闭装饰动画、辉光、模糊和可选画布效果，但不改变功能；正式版前不依赖
  运行时工具检测自动切换；
- 无限动画仅用于真实进行中的状态、加载、少量呼吸提示和低帧率吉祥物；离屏、窗口失焦或任务
  停止后暂停；
- WebGL 三场景属于 v0.6.1 视觉方向：全应用深色背景使用星云云幕，指挥台使用全息核心，Release
  使用立体展台。每个场景必须具备 off/static/animated 三档、CSS 兜底、上下文丢失恢复、明确
  性能预算以及离屏/失焦暂停；浅色、高对比、资源节约和 reduced-motion 按既有降级链收敛；
- 卡片指针倾斜与聚光只作为 animated 档增强，最大倾角和光斑透明度由 Token 约束；键盘、触摸、
  reduced-motion 与 effects-off 使用无倾斜的稳定卡片。

## 8. 模块视觉语言

### 8.1 指挥台

指挥台是无侧栏的恒定落点和品牌第一印象：VUA 字标、全息核心、`Ctrl+P` 命令入口、四张模块
速达卡和环境状态带共同组成。全息核心使用 WebGL animated/static/off 三档，CSS 核心在所有降级
环境中保留完整入口与状态信息。指挥台是唯一允许紫橙低透明氛围同框的页面；操作控件仍只使用
一个主辖区色。

### 8.2 环境部署

使用“结论先行、问题可修复”的状态总览。大型红/绿/琥珀状态灯只在这里出现；未检测时使用中性

### 8.5 Assembly

Assembly 可以使用橙色轨道、检查点和回环箭头表达计划、执行、等待确认、阻断与恢复。
每个演出状态必须由真实任务事件解释。执行与恢复是 Assembly 内的任务进展，不显示独立 Production
阶段。车间演出继续作为核心视觉投资：素材缩为零件上车、搬运、对位、锁紧、节点点亮、缺依赖
挠头和回滚倒退均由真实任务事件驱动；流程逻辑冻结后提升演出密度，不以排期理由删除该方向。

车间＝执行状态面（0.7.16，U16 用户裁决消费切片二，proposal 029 A6）：车间只作状态
显示——呈现当前执行链的 解析 → 计划 → 装配 → 记录 各卡（与配方页发起面消费同一容器层
store 与 Gateway 端口、同一任务中心权威快照；计划批准与组装发起在配方页选中态完成，
状态面零发起动作，只保留读取类刷新）；本会话无链身份时呈现诚实空态，「前往配方页」为
纯导航（023 投影纪律：零记录身份跨页，车间页自取权威事实）；任务需要处理
（waitingInput/paused/failed）时指路任务中心，不在状态面自建第二恢复决策面。回放视图
是状态面的录制带形态（真实任务事件驱动 DNA），消费在其上扩展、不另起第二呈现系。
素材直产链（production-use-case v0.1）发起位自车间退出、落位仓储页动作位（未决项 1
桌面落形，操作者第 162 批 2026-09-22 裁定；wire 面与组件行为零改动；capability 未就绪

### 8.7 项目与包管理

使用 Compact 表格、事实行和能力徽标。所有安装、升级、移除先显示联合变更预览；ALCOM/VCC 只
显示经能力检测证明的项目兼容范围，不使用第三方应用的品牌外观暗示嵌入。项目兼容不再持独立
二级页（026 B，用户 2026-09-18 裁决）：其读面段（项目检测、备注、锁状态、环境状态、副本导入
确认链）作为「项目兼容」分区呈现在包管理器页尾部，分区不挂包引擎能力门控；写操作交接维持
引导性呈现，无词表与能力事实不虚构交互形态。

项目创建（026 A5）为单段写命令，不走联合变更预览：全新项目目录无既有状态可比对、无摘要可
绑定，用户显式表单提交即确认。入口随创建能力事实行门控，无事实不渲染。表单为父目录路径与
项目名称输入，不虚构目录枚举。创建成功即在册（列表刷新即见）；创建不幂等，目标目录已存在
等拒绝如实行内呈现。

模板枚举呈现（027 F5 消费切片）：创建区块随 packages.templatesOps 能力事实行门控挂载模板
枚举（packages.listTemplates 环境级配置面，页面局部承载，不进快照）——枚举就绪时模板下拉
替换手填输入：默认项＝「使用后端默认模板（留空）」（026 A5 留白语义原样），模板行显示名逐
字用 name（＝id 冻结同值投影，绝不虚构更友好标签），选中项以 id 作 packages.createProject
template 参数原样传递。回落纪律：能力行缺席、空数组（诚实零模板应答——目录根缺失是事实
非错误，绝不渲染成错误、绝不虚构模板清单）、typed 失败与不可用一律回落现行手填输入＋留空
＝后端默认解析；typed 失败携错误码原词呈现，与能力缺席的呈现严格区分，失败不冒充空清单。

设置面文案纪律（027 F1，用户裁决 U14）：订阅、本地包注册等设置面操作的 UI 文案如实表述
共享语义——与 VCC/ALCOM 共享同一份包管理设置（settings.json），改动双方立即可见；VUA
不修改你的项目文件，外部导入默认克隆为副本后修改。设置面文案不得使用「隔离后端环境」「绝不
修改 VCC/ALCOM 设置」等与共享实现不符的排他表述；项目文件面只读与克隆优先语义不变。

仓库发现呈现（027 F2 消费切片，IA 表态 2 落地）：仓库订阅与仓库订阅管理两分区合并为单一
「仓库」分区（纯呈现层重组，能力事实行与词面照旧）——订阅列表行为主体，行内展开即该仓库
可装包浏览面，浏览入口随 packages.repoCatalogOps 能力事实行门控（环境覆写置真前如实缺
席，无事实不渲染）；搜索框是已取得目录事实的呈现层过滤（packageId/displayName），不另立
查询形状，批量 packageId 过滤由词面承担。诚实呈现纪律：cached=false 行＝「已订阅·缓存未
建立」空态，不隐藏不伪造成空目录；latestVersion=null 行如实呈现「无合资格版本」，绝不渲染
「已最新」类断言；cacheSourced=true 呈现「缓存数据」信息标注，信息性非失败；author 与
compatible 系冻结词面刻意缺席，呈现层不发明；displayName=null 以 packageId 兼任显示名；
typed 失败照原词呈现（repo_not_found 逐字透传），失败不冒充空态。

已装包更新感知呈现（027 F3 消费切片）：已装表新增「可更新」列，呈现为冻结判定词面的三态
诚实投影——updateAvailable=null（判定未执行）如实空显并携悬浮说明，绝不渲染「已最新」、
绝不以默认 false 填充（024 表态②用户裁定）；false＝「当前过滤条件下不存在严格更新版本」
精确词面，不泛化为「无更新」断言；true＝呈现「有更新」并提供行内升级键（随
packages.installOps 能力事实行门控，无事实不渲染），升级键复用 A2 安装面 version=null
语义（解析器选最新稳定版），不新立升级动词。双族协商纪律：v0.1 族应答（族常量
vua.packages-installed/v0.1 辨别）无判定事实，该列整列诚实空显，既有呈现零回归；
cacheSourced=true 仅 v0.2 族应答携带，在表格上方呈现「缓存数据」信息标注（复用 catalog
措辞），信息性非失败，v0.1 族应答绝不虚构标注。

仓库生命周期呈现（027 F4 消费切片）：订阅行行内挂启停与刷新控制，随
packages.repoLifecycleOps 能力事实行门控（一行服务三方法；环境覆写置真前如实缺席＝控制
不渲染，订阅行照常呈现——降级非错误，无事实不渲染）。启停语义如实口径（W25 只读证据裁
决 (c)：VCC 无任何启停状态）：启停位是 VUA 自有状态，与 §8.7 设置面共享语义表述纪律区
分——禁用词面如实表述「禁用的仓库保留在订阅列表，其包不再参与浏览与安装解析；不写
VCC/ALCOM 共享设置」，此为与实现相符的如实陈述而非排他宣称。禁用在列不隐藏：v0.2 族应
答（族常量 vua.packages-repos/v0.2 辨别）enabled=false 行照常渲染并带「已禁用」标注；
v0.1 族应答无 enabled 位＝启停状态不可知，启停控制不渲染（不猜测），刷新控制不依赖该位
可独立渲染；repoId 缺席行在生命周期词面可达范围之外，不渲染任何控制。刷新收据两臂皆成
功：cacheUpdated=false（etag 未变）如实呈现「缓存已是最新」信息词面，绝不渲染成错误。
typed 拒绝携原端口码 detail 原词呈现，与能力缺席严格区分；能力缺席（capability_missing）
与引擎缺席（unavailable）呈现区分；重复启停不宣称幂等，拒绝如实呈现。

### 8.8 Overlay

Overlay 使用比桌面更高的文字对比、更少的层级和更大的操作目标，只展示稳定快照和语义动作。
不使用毛玻璃、复杂背景或长列表；桌面回退始终可见。


### 8.9 全局件：启动开屏与通知中心

启动开屏是品牌第一帧，不是加载遮罩的替身：方形柱格自顶部落满与中央 VUA 字母紫橙渐变描边
为固定仪式。退出由真实启动链驱动——动画预算播完且渲染／网关／提供者／绘制四里程碑全齐才
淡出；未齐转等待态（方柱呼吸＋如实等待字幕），硬上限到点必退，主界面以自身诚实缺席呈现接
管。Escape 与点击即跳过。全局动效压平（reduced-motion／特效关）时动画整体摊平、驻留缩短、
不等里程碑。左下角版本角标读取构建期注入事实（版本·提交·dirty）；更新角标只在「有更新可
用」时上屏，检测失败与已最新不打扰。

通知中心（顶栏铃铛）与底部任务条共用同一通知投影——同一事实源两处呈现，不发明各自口径；
任务引擎能力非 ready 时入口整条不出现（§2.6 无事实不渲染，而非禁用置灰），铃铛徽标＝进行
中任务计数。面板为全屏毛玻璃 backdrop ＋实底面板：header 自带 backdrop-filter 会囚禁
fixed 后代，故 backdrop 与面板一律 portal 到 body，模糊只放在全屏 backdrop、面板本体不模
糊（合成层残影教训）。开启时焦点入面板，关闭还回铃铛（用户已他处落焦则不抢）；外击／
Escape／面板外滚动（面板内列表滚动不关闭，W25 真机修正）／失焦关闭；动效压平时退场
不等动画窗。

通知条目纪律：默认只显示进行中任务；「显示已完成」开启且未被清除的终态任务才作为通知出现。
清除动作仅对终态通知开放——清除的是通知不是事实，任务权威仍可经任务面查询（§6.2）。任务
行标题诚实投影：已登记身份的任务用登记标题，未登记任务如实给类型词「后台任务」，裸
taskId 不充当描述（投影不到的事实不编造）。行主区点击＝回任务来源页，活动／终态两态一致，
不静默无响应。行内状态图形与状态词承载成功／失败事实，重试／清除等动作按钮各司其职；面板
关闭 ✕ 只承担关闭面板语义，与清除通知、任务失败呈现不混用。

## 9. 可访问性、国际化与性能

- 核心流程仅用键盘可完成；焦点可见、顺序可预测、浮层关闭后焦点恢复；
- 状态不只依赖颜色；表单错误关联具体字段；图标按钮具有名称和 Tooltip；
- 支持深色、浅色、`forced-colors` 和至少 200% 文字缩放；基础窗口验收包含 960×600、125% 与
  150% DPI；
- 用户文案走语言键，组件内不硬编码可见字符串；领域功能名优先使用当前语言中玩家熟悉的表达，不强制附加英文；品牌名与内部 ID 保持不变（用户 2026-09-20 批准 i18n 审阅修复）。已知诊断按稳定代码显示本地化说明，原始消息保留供排查；日期和原生对话框跟随应用语言；
- Fixture 只在开发构建可达并明确标识；生产构建默认展示真实数据或诚实空态；
- 大列表使用虚拟化或 `content-visibility`；动画失焦暂停；高成本效果必须有测量结果和关闭路径；
- Recipe 图谱若实现，100 节点目标 60fps、最低 30fps，并保留列表替代。

## 10. 完成定义

页面进入可交付状态前至少验证：

1. 主要目标、对象、状态、下一步和恢复入口清楚；
2. View 只通过 Gateway 提交意图，不含业务规则或特权调用；
3. 深色、浅色、高对比和辖区颜色对比度通过；
4. 键盘、焦点恢复、非拖放替代和屏幕阅读器语义通过；
5. Loading、empty、error、blocked、success 与 capability unavailable 均有诚实表现；
6. 动效在 reduced-motion 和 effects-off 下功能完整；
7. 高影响操作展示影响范围和恢复条件；
8. Fixture 不进入生产构建；
9. 960×600、最大化、125%/150% DPI 和长中日英文案下不丢失关键操作；
10. 五个一级 Tab、三级折叠梯子、平行四边形控件和透明飞出菜单在鼠标、键盘、缩放与
    reduced-motion 下通过；侧栏生长不移动相邻条目；
11. WebGL 星云/全息核心/立体展台逐一验证 animated/static/off、CSS 兜底、上下文丢失、失焦暂停
    和性能预算；页面不引入未经测量的全墙模糊、持续视差或布局重排动画；
12. Recipe 三视图与 Release coverflow/展台保留完整降级路径；
13. 新视觉元素能解释实际用途，关闭后不损失信息。
