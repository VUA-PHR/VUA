# ADR:VUA 实例身份与多实例边界

[English](vua-instance-identity_EN.md) | [简体中文](vua-instance-identity_ZH.md)

> 状态:Proposed(提案)
> 日期:2026-09-04
> 范围:桌面壳、环境检测、安装器与更新器(M9/M10)

## 背景

pre-alpha 的 VUA 没有安装器,便携副本与并行开发构建使多实例成为常态。缺乏管理时会发生
四类冲突:同一项目的并发操作、更新时目标 exe 正在运行、不同版本写同一本地数据目录、自定义
协议/文件关联被错误实例应答。项目级突变已有围栏(任务存储中按 `ProjectIdentity` 带代际的
租约)。生态证据:VCC 以 stable/beta 双实例并存且数据目录分开(真机观察到
`VRChatCreatorCompanion` 与 `VRChatCreatorCompanion-Beta`)。

## 决定(提案)

1. 实例身份为三元组:**(渠道,安装形态,版本)**。渠道:`stable` / `beta` / `dev`;
   安装形态:`installed` / `portable`。
2. 每个安装根携带**标记文件**(产品、渠道、版本),路径相对固定:installed 由安装器写入,
   portable 随根携带。自我检测只读标记——绝不扫描。
3. **数据目录按渠道隔离。**数据目录记录写入它的 schema/processor 版本;旧实例打开更新的
   数据目录时**拒绝**(版本门),不做尽力兼容读取。
4. **应用级单实例**:桌面壳启动时获取按渠道命名的互斥体;第二实例在呈现正在运行实例后退出。
   环境检测器把探测结果作为 presence(`another_instance_running`)上报——只是事实,severity
   归前端。
5. 环境检测项 `vua_instances` 在本契约与安装器落地前**不做**——对着臆造路径的检测是虚构。
6. 跨实例的项目突变继续由既有 `ProjectIdentity` 租约围栏,与实例身份无关。

## 后果

安装器(M9/M10)与未来的 `vua_instances` 检测器共享同一契约,而不是各造一套。便携与
installed 同渠道并存;stable/beta 数据永不混合。版本偏差导致的状态损坏被版本门拦住。成本
是一个标记文件加一个互斥体——本决定不要求任何注册表痕迹。

## 被否决的替代方案

- 跨安装、跨版本共享单一数据目录:否决——版本偏差写入正是本 ADR 要防的损坏模式。
- 在安装器存在前扫描常见路径以发现其它安装:否决——没有契约的检测只是在检测假设。
- 仅靠项目级身份(现状):否决——它能围栏项目突变,但应用级互斥、更新与协议交接仍无定义。
