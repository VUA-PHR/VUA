## 产品定义

VUA 是以 Windows 为首要平台的本地 VRChat 桌面生产环境，面向希望从素材发现、环境部署一路
完成 Avatar 生产与运行工具配置的玩家；核心服务对象是不熟悉 Unity、甚至不清楚自己需要什么
的 VRChat 玩家（用户裁决，2026-09-22）。产品采用 Recipe-first、local-first 和可恢复执行原则，
让新用户经由 Wizard 按目标、设备与当前状态选择路径，不再要求所有玩家走完一条固定大流程
（完整流程覆盖仍保留为有价值的能力），同时为熟练用户提供可检查、可复现的生产记录。

## 已接受的产品组成

1. **Electron 桌面应用**：React、TypeScript、Vite Renderer，隔离的远程网页视图、Session、
   下载交互、桌面窗口和窄化 Gateway；
2. **Orchestrator**：通过可替换的版本化 Provider 边界提供持久任务、计划、批准、恢复、取消、
   Build Record 与适配器协调；
3. **Avatar MegaFactory**：拥有以下用户流程和内部模块：
   - Warehouse、Recipe、Assembly、Release 用户流程；检查能力归入制作记录与通知中心，不再要求
     独立 Inspection 用户页面（用户裁决，2026-09-22，见「制作范围与产品裁决」）；
   - 原生素材浏览、授权下载、内容管理以及 BLM、VAE 等外部来源适配器；
   - **素材入口语义（用户裁决，2026-09-07；触发时机澄清随 W15 复验，2026-09-08）**：默认路径为
     直接使用原始 `.unitypackage`（面向新手定位）；「生成 VPM 包作为替代」的**目标触发时机为
     素材导入时**（自动生成，替代原始 UnityPackage），与「生成后删除原始素材」同为**实验性**
     能力，收拢于设置-实验性位置呈现；当前版本该自动生成**尚未接线**（界面已如实标注），
     生成仍由用户在仓储条目手动发起，导入时挂点与编排语义随 M5 接线；VPM 包生成结果始终与
     直接导入结果明确区分（`unityValidated` 与实验性离线输出）；
   - **BDL（Booth Database Local）**：管理商品、子商品、文件、协议、别名、兼容关系、来源记录
     与搜索状态，只通过 AMF 应用服务提供能力。
4. **环境部署**：对硬件、VR 运行环境、Unity、VRChat 与相关工具执行前置侦测、引导式部署和边界
   收紧的恢复；缺失这些能力会阻断游玩或 Avatar 制作；
5. **项目管理**：VUA 中最高频的「项目管理」实际是 Recipe 与 Release 两个模块；提供基于
   `vrc-get` 自建的 VUA 包管理器，其第一形态是 **Recipe 驱动的自动解析与导入**——依据
   Recipe 输入自动寻找并导入对应包，而不是用户首次进入就要手动导入一系列插件的模块；
   手动逐包管理为次要形态（用户重申与裁决 U14，2026-09-19）。对 ALCOM/VCC 管理的项目
   执行**只读兼容**，唯一写路径是用户显式选择的「导入为 VUA 管理的副本」（用户裁决 U3，
   2026-09-08；允许/禁止清单、副本规格与收紧条款见「明确边界」；`1.0.x` 边界内对原项目
   写能力一律 false）；**设置面例外（用户裁决 U14，2026-09-19）**：VPM 包管理设置
   （`settings.json` 的仓库订阅与本地包注册表面）与 VCC/ALCOM 共享同一文件，VUA 可读写、
   改动对双方立即可见——该例外只及设置面，项目文件面维持 U3 不变；
6. **Unity Bridge**：精确以全球版 Unity `2022.3.22f1` 为生产目标的版本化、确定性 Editor 操作
   协议；历史 Editor 项目通过已定义的迁移边界接入；
7. **桌面 Overlay**：通过稳定应用服务展示引导、状态和运行时工具信息，属于 `1.0.0` 产品
   组成；**VR Overlay**：移出 `1.0.0` 范围（用户裁决，2026-09-06），保留为 `1.0.0` 之后的
   方向锚点（见[开发计划大纲](development-outline_ZH.md)的 v1.1 展望）；
8. **集成运行时**：通过可选托管或外部连接适配器提供面捕、动捕、Avatar 优化等接近原生体验的
   重大可选能力；该方向保留在产品边界内，但在正式版 `1.0.0` 发布后才开始实施；
9. **社区插件接口**：面向可选增强与定制的版本化协议、能力声明、生命周期、任务、权限与兼容性
   规则。

## 制作范围与产品裁决（用户裁决，2026-09-22）

> **本节为已接受的产品方向，不代表相关界面、协议或执行链已实现，也不构成任何真机验收声明。**
> 本节取代本文件及关联文档中与之冲突的旧表述（五阶段固定流程、独立 Inspection 页面要求、
> Recipe 完整复现任意工程的暗示、VUA 穷举测试上游能力）。**冻结协议与现有数据格式不因本次
> 文档合并自动改变**；确需变更时经后续版本化迁移完成。本节不授权删除已有数据或静默覆盖
> 用户工程。

### 已确认范围

**产品定位与新手引导**：核心服务对象是不熟悉 Unity、甚至不清楚自己需要什么的 VRChat 玩家。
完整流程覆盖仍有价值，但由 Wizard 依据目标、设备和当前状态为用户选择路径，不要求所有玩家
走完一条大流程。设备准备增加 Quest 初次激活教程，区分独立运行与连接 PC 的使用路径。引导与
教程不能代替用户完成账号认证或平台授权。

**Recipe＝可叠加的一组修改**：Recipe 表达素材组合与明确、受支持的选项，语义类似 mod 管理器。
新 Recipe 叠加到当前 Avatar；未提及的已有素材和设置默认保留，不得因未出现在新 Recipe 中而被
删除。删除必须是明确操作；冲突需要明确处理。Recipe 不承担任意 Unity 工程、场景或全部手工
创作的完整复现。

将 Recipe 应用到已有 Avatar 时提供四个选项：① Recipe 设置优先（冲突的受支持字段采用 Recipe
值）；② Avatar 设置优先（冲突字段保留现有 Avatar 值）；③ 新建 Avatar 承载 Recipe（推荐）；
④ 取消操作。四个选项只处理 Recipe 涉及的字段，不授权覆盖无关内容。新建 Avatar 不等于必须
新建 Unity 工程；同一 Avatar 的素材增删改也不应仅因此要求新建工程。现有外部工程的所有权
限制（见「明确边界」ALCOM/VCC 条款）另行适用。

对象无法确定与数值冲突不同：不能用「Recipe 优先」掩盖对象定位歧义。没有可靠基线时，也不能
把所有差异都认定为玩家手改。

**Recipe 分享与复现边界**：可分享的内容＝BOOTH 素材引用＋明确支持的布尔、枚举、整数、浮点
选项（例如颜色、亮度、色相、局部位置、旋转和缩放）。不包含：自定义贴图文件、自定义 FBX、
付费素材本体，以及将网格/像素等任意内容编码成数字后变相纳入分享。SNS 粘贴文本与文件可以
承载同一份声明；文件本身也可以只是长文本，不需要因此变成 Unity 场景包。

**素材来源（分享时再补，尽量少填）**：导入和本地使用不要求立即填写 BOOTH ID。真正分享时，
只要求补齐本次 Recipe 涉及且缺少来源的素材。优先通过已购库/商品网页点选、关键词搜索候选
列表、批量关联完成，不以逐个键入数字为默认体验。已确认关联应记住，避免重复劳动——人工补充
尽量少、尽量晚，一次完成后不再重复。BOOTH ID 属于作者或用户的来源声明，不是 VUA 对真实性、
未修改状态或可复现性的认证。错误关联属于 UGC 内容责任；VUA 仍应如实报告解析失败，并对自身
执行与应用错误负责。复现者通过自己的 BOOTH 权限重新获取素材。来源声明不授予购买权限，也不
要求 VUA 证明本地包与商店原件完全一致。

**BDL**：保留已存在的基础存储、素材身份、来源关联与目录能力。自动兼容性证据收集为实验功能，
默认关闭；开启后尝试从用户实际的 BOOTH 浏览和 Unity 使用过程中收集证据，不恢复全站云端采集
方向。关闭自动收集不能关闭基础存储、普通导入或 Recipe 来源补充。本地证据查看、修订的方向
保留；具体界面与可修改范围仍需定义，不能直接推导成任意数据库编辑权限。没有证据代表未知，
不能当作兼容或依赖已解决。

**Inspection 收进制作记录**：不再要求独立 Inspection 页面。用户确认制作、车间开始投料时，
Release 建立该次运行的占位记录。制作问题同时通过通知中心和记录状态提示；两处都能打开对应
的说明、日志及后续操作。关闭通知不等于问题消失。运行中的占位记录不能冒充已完成的
Build Record。页面调整不删除检测服务、恢复准入或证据记录能力。

**MA 与 SDK 职责**：接受 Modular Avatar 已声明的能力边界，不再由 VUA 穷举测试 MA 的全部能力。
VUA 验证自身接入、参数、对象选择、调用顺序和代表性实际流程；标准上游使用也能复现的问题再
向上游反馈。构建和目标平台技术限制优先复用官方 SDK 检查，不维护重复规则。素材缺失、依赖
安装、Bridge 执行与恢复仍是 VUA 的责任。未执行的检查不能显示为通过。最终上传由用户在官方
SDK 中完成；技术检查不能保证外观与行为符合玩家预期，需要明确说明。

### 明确延期

基于 egui、Slint 等技术的独立轻量 UI 无限期延后至核心功能稳定之后；不承诺启动日期。该延期
不取消现有 Electron 资源节约模式。

### 待验证与未决

以下事项**未决**，本节的任何措辞都不构成其中任何一项已解决的暗示：

- **对象定位（未决）**：同名骨骼、跨工程定位、重复应用必须实机验证；当前方案不能默认视为
  可靠。
- **Recipe 字段与编码（未决）**：产品能力方向已定；字段白名单、定位标识、版本化格式未定。
- **冲突处理实现（未决）**：四个选项已定；差异识别、预览与保护的具体实现待验证。
- **依赖降级路径（未决）**：自动取证关闭或解析失败时如何完成依赖补齐，仍需明确实际流程。
- **BDL 人工修订（未决）**：查看/修订方向保留；具体权限和交互尚未冻结。

## 扩展与集成信任边界

VUA 按数据接触和信任关系划分扩展：

| 边界 | 产品含义 | 访问规则 |
| --- | --- | --- |
| Kernel 与本地 UI | 稳定的应用启动、安全权威、Gateway 强制与受控表现层 | 扩展使用其公开表面 |
| Core | 仓库拥有、经过评审并直接随正式制品构建的可信产品行为 | 使用所属 Orchestrator 应用用例和端口 |
| Plugin | 通过公开、版本化能力边界工作的独立增强包 | 显式授权定义其全部权限 |
| External | 独立与 Unity、VRChat、SteamVR、设备或其它公开外部边界交互的软件 | 保持独立状态；VUA 侧适配器归类为 Core 或 Plugin |

环境部署、追踪、优化、可访问性和外观作为具体条目中的自然语言用途说明。面向社区
维护的[工具目录](tool-catalog/README.md)登记具体条目的分类与证据。产品边界批准范围，架构确定
实现所有权，发布门根据能力和行为派生风险。

## 稳定产品原则

- **Recipe-first**：先选择素材与目标，再创建或修改 Unity 项目；
- **本地优先**：购买会话、订单、下载、付费素材和生产状态保留在用户设备；
- **确定性生产**：可规范化的 Unity 操作通过 Unity Bridge 和 Build Record 复现；
- **能力感知**：官方、开源和社区工具通过适配器并存，界面诚实显示可用能力；
- **可恢复**：长任务具有明确状态、取消、重试、恢复和人工接管路径；
- **最小权限**：远程网页、插件和第三方组件只获得完成任务所需的能力。

## 明确边界

- BDL 是本仓库内 AMF 私有的本地数据模块，由 AMF 提供应用服务；
- Electron Main 拥有远程网页、Session、Cookie、权限与下载传输的桌面机制和安全强制；AMF 拥有
  素材获取用例、任务、来源验证、文件检查与 Warehouse 映射。双方通过规范化应用值交互；
- BOOTH 会话、订单、已购文件与凭据保留在用户设备，平台购买、付费、身份、年龄与访问控制保持权威；
- 仓库与云端 CI 测试使用与生产输入结构一致、但不含真实商品或用户内容的合成夹具；
- 本地只读兼容性测试可以通过平台正常公开入口访问 BOOTH 公开页面，并遵守平台的认证、付费、年龄和
  访问控制；网页响应、截图及商品元数据不作为测试夹具提交；
- 开发者可以在本地使用自己合法取得或购买的 Unity 素材进行集成与冒烟验证；素材、用户项目、测试
  配置和测试产物保留在本地，不进入仓库或云端 CI 制品；
- [Unity Editor 兼容政策](compatibility/unity-editor_ZH.md)规定全球版 `2022.3.22f1` 是唯一生产
  目标；`2019.4.31f1` 和 `2022.3.6f1` 是迁移来源；其他 Unity 版本统一报告与生产目标的差异并
  保持项目文件原状；团结引擎当前暂不支持；
- **ALCOM/VCC 项目兼容（用户裁决 U3，2026-09-08，第三方仲裁复核后）**：对 ALCOM/VCC
  管理的原项目只读。**允许**：发现和识别；读取版本/包/SDK/兼容性/环境状态；生成诊断、计划
  和处理建议；将写操作交接给对应管理器；用户显式选择后「导入为 VUA 管理的副本」。**禁止**：
  在原项目内安装/移除包；修改 manifest、项目配置、素材或 `.vua` 作业文件；写入 ALCOM/VCC
  的注册表/数据库/设置/缓存；静默把原项目改标为 VUA 管理。**「导入为 VUA 管理的副本」
  规格**：新项目路径＋新项目身份；明示预计磁盘占用；不复制可再生目录与旧任务状态；导入后
  重新 Inspect（不继承原项目的确认/快照）；保留来源关系便于返回。**Rationale**：VUA 项目锁
  只能协调 VUA 实例，ALCOM/VCC 不遵守——「允许写＋提示冲突」会给出不存在的安全保证；
  双方理解 VPM 格式不等于拥有兼容的事务与恢复机制。**收紧条款**：`1.0.x` 边界内 ALCOM/VCC
  写能力一律 false；未来仅当上游提供可验证的事务/锁/受支持写接口后，经**新用户裁决**方可
  开放，不能只靠提示风险；**设置面例外（用户裁决 U14，2026-09-19）**：禁止清单中「写入
  ALCOM/VCC 的注册表/数据库/设置/缓存」一条，对 VPM 包管理设置文件（`settings.json` 的
  仓库订阅与本地包注册表面）豁免——该位置是 VCC/ALCOM/vrc-get 共享的约定设置文件，VUA
  经裁决开放读写且改动双方立即可见；`vcc.liteDb` 等其余存储面维持禁止不变，项目文件面
  维持 U3 只读、外部导入默认仍为克隆后修改复制品；
- **远程网页浏览与窗口/协议边界（用户裁决 U7②＋U9，2026-09-09）**：Web 浏览按
  **白名单先行**执行——白名单内域名直接浏览；白名单外**只提示、不禁止**（确认后放行，
  内容可达性不受影响）。**购买流程当前不做**（非永久；取决于与 BOOTH 官方的后续联系）；
  下载主机域在真机验证后**逐域提案批准**。新窗口与外部协议按**四分法**：(1) 网页类
  新窗口（http/https）永不创建独立窗口——白名单内转入当前内嵌视图打开，白名单外
  提示确认后同样转入当前视图；(2) 伪协议窗口（`javascript:`/`data:`/`blob:`/`file:`）
  无条件拒绝，无放行路径；(3) 外部协议经**独立确认层**：http/https 白名单外先提示
  再交系统浏览器；`mailto:`/`steam:`/`vrchat:`/`discord:` 等显式协议清单逐次弹确认框
  显示完整目标、不提供永久免确认；未知协议默认拒绝；(4) **手势要求**：协议启动必须
  由用户点击触发，页面自动触发（脚本/meta refresh）一律不执行；原生新窗口创建一律
  拒绝。**Rationale**：内容可达性（只提示不禁止）与本地特权隔离（不放出独立窗口、
  不放行未确认协议）并行不悖；远程内容永不获得本地特权（见「扩展与集成信任边界」）。
- 第三方组件的“可选内置”必须逐项满足许可证、再分发、更新和签名要求；
- EAC 进程终止是默认关闭的实验性高风险恢复动作，每次执行都必须由用户再次确认。它可能导致
  游戏中断、EAC 状态异常；极端情况下可能触发平台或账号安全检查并出现账号异常。该能力仅限
  已核验允许清单中的用户态残留进程，不得停止服务/驱动、修改 EAC/VRChat 文件或规避反作弊；
- 第一阶段提供能力协议与安全模型，市场治理由后续发行决议安排；
