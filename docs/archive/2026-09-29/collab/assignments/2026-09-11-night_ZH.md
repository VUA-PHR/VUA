## 4. 易踩坑点（本周真实事故 + 任务特定）

**协作机制事故（均已发生过，别再犯）：**

1. **首跑竞赛**：合并后首次 `cargo test` 曾报 44 套件（实际 67）——验收数字以**两次稳定
   复跑一致**为准；
2. **状态文件整体替换**曾截断文件/留下双 front-matter——覆盖写后必须 `collab:brief`
   自检结构再提交；
3. **"collab only 免测"误标**：夹带任何非 collab/ 文件的合并必须全量测试；
4. 合并前 `grep -r '<<<<<<<'` 防冲突标记混入（发生过一次）；
5. **先提交后跑测**是顺序违规（发生过一次）：测试绿 → 提交，顺序不可换。

**任务特定坑：**

6. **无证据（empty）与检测失败（failed）是两种状态**，不得折叠成同一空态（诚实纪律）；
7. **就绪判定归属**：后端快照只给在场事实，headline 判定留在表现层模型——不要让后端
   直接给"就绪"结论；
8. **inspection-evidence 是草案**（proposal 016，未冻结）：可消费但标注草案态；
   `official_sdk_rating` 是保留值，SDK 交接切片落地前**禁用**；
9. **019 红线**：森林绿源码不入 git；推送 origin 前 3 轮 Reviewer 审阅须含 forest
   零泄漏核查；
10. **019 批 B 刚落地的草稿身份语义**（recipeId+revision 随 UI 切换保留）不要破坏；
11. 桌面 check 的 `type: module` 警告是老噪音，不是失败；
12. 切片完整性优先于所有权（TICK v1.4）：切片内全部层由负责角色完成，但**跨域切片
    合并回 main 由集成验收**。
