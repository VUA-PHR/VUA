## Semantics

- **One inspection run = one document**: `{ schemaVersion, inspectionId,
  avatarRef, performedAt, bridge, dimensions[], overallStatus, notes? }`.
- **Five-dimension closed set** (v0.1): `functional` / `performance` /
  `dependencies` / `lighting` / `upload_readiness`. Per dimension: `status`
  (pass|warn|fail|unavailable) + `basis` + `checks[]`.
- **Identity**: `inspectionId` is a uuid v7 (generated by the AMF side;
  identity convention isomorphic with production-evidence's `evidenceId`).
  Consumers reference it, never re-derive it.
- **basis honesty discipline**: `bridge_typed_checks` = typed Bridge check
  receipts; `bridge_local_estimate` = Bridge-local structural estimation
  (analyze_performance discipline: explicitly **not an official VRChat
  rating**); `official_sdk_rating` = **reserved value** — disabled until the
  official SDK handoff slice lands (not schema-forbidden, forbidden in
  vectors and review); `static_analysis` = static file/package analysis
  without a Bridge run; `none` = not observable in this run.
- **unavailable dimensions pinned**: schema if/then forces
  `status=unavailable` ⇒ `basis=none` and an empty `checks` array — a
  dimension without a producing operation must be stated as absent;
  **absence is evidence, checks are never fabricated**.
- **Aggregation rule (declared before implementation, proposal 016 §4)**:
  any dimension fail → `overallStatus=fail`; else any dimension warn or
  unavailable → `warn`; else `pass`. **Unavailable degrades to warn — an
  incomplete inspection must not read as a clean pass.** The rule is
  asserted by the vector tests.
- **bridge transcription discipline**: `bridge.editorVersion` /
  `bridge.bridgeSchemaVersion` 〔1|2|3〕 / `bridge.operations[]` (operation +
  commandId + status) are a **transcription, not an interpretation** of the
  run environment (Build Record jobs[] discipline; commandId is the receipt
  identity / comparison key). check `code` is a dot-namespaced typed code
  (Bridge diagnostics convention); `metrics` transcribes observed values
  only, never derived guesses.
- **dependencies dimension single-layer ruling** (definition right exercised
  per proposal 016 arbitration point 4, written into the frozen semantics):
  the dimension means **Avatar asset reference integrity** (produced by
  `inspect_avatar_references`, basis=`bridge_typed_checks`). **Manifest
  declaration completeness is NOT merged in** — it is a project-level fact
  carried by project-inspection v0.2; consumers needing both facts read the
  two vocabularies side by side, **reference, do not copy** (the 012
  `evidenceIds` precedent).

## Producers and consumers

- Producers: the Bridge inspection operations (v1 `validate_avatar` typed
  checks = functional; v1 `analyze_performance` local estimate = performance;
  the v3 read-only `inspect_avatar_references` / `inspect_lighting` /
  `inspect_upload_readiness` = dependencies / lighting / upload readiness) —
  driven by the core-side task-based `inspection.requestRun`, transcribed
  verbatim, aggregated mechanically, published append-only exactly-once
  (`{inspectionId}.json` identity addressing); **a zero-receipt run is a
  typed failure and publishes nothing** (honest-absence discipline).
- Consumers: `inspection.get` (identity-addressed, returns the evidence body
  verbatim) / `inspection.list` (identity summary rows, **never inlines
  dimensions/checks** — the 012 reference-not-copy rule), vocabulary row
  `schemas/inspection-queries/v0.1/` (data domain, separate freeze batch);
  desktop presentation follows the M7 Inspection page consumption slice.
- This protocol declares no resolution lifecycle (deliberately not
  isomorphic with production-evidence's `resolution` field): inspection
  evidence is an **immutable observed fact**; later handling facts reference
  it, they never rewrite it.

## Boundary with BDL

BDL (bdl v0.1) does not store inspection evidence — its admission rule is
material-acquisition observation facts (data-side stance in proposal 011;
three-role consensus in proposal 016 §5). The evidence body persists in the
AMF production persistence domain's fifth document store
(InspectionEvidenceStore: append-only, hard_link exactly-once, identity
addressing, absent root = honest empty state).

## Stable error codes

This protocol has no command face and adds no error codes; a run's failure
semantics follow the task face (`inspection.requestRun` acceptance follows
the job.execute form; zero receipts = typed failure and no publication),
and read-face error codes follow the inspection-queries v0.1 vocabulary row
(e.g. `vua.inspection.unavailable` honest absence).
